# crudelab — 原油研究平台

數據 → 指標 → 模型 → 推演 → 報告。四期都已完成：骨架、地域價差與煉廠盈利、供需平衡、地緣與推演與報告。
版面以電腦端為主。

系統是**兩個獨立的站點**，共用同一份數據：

| 站點 | 預設地址 | 做什麼 |
|---|---|---|
| 前台 | <http://127.0.0.1:8000> | 研究：價差、供需、煉廠、事件、推演、報告、問答 |
| 後台 | <http://127.0.0.1:8001> | 管理：數據導入、序列、指標、參數、數據源、日誌 |

前台的接口裡不包含導入數據、改參數這些操作，後台的接口裡不包含研究功能。部署到服務器時可以只開放前台。

架構、約定和擴展方法見 [docs/architecture.md](docs/architecture.md)。

## 現在能做什麼

**前台**

- **地域價差**：基準價差、月差結構、各油種現貨絕對價、品質價差、運費、中國到岸成本、套利窗口。
- **供需平衡**：
  - 兩張平衡表：全球液體燃料（EIA 口徑，月度，含預測期）、美國原油（周度，含未解釋項）。
  - **情境**：你的判斷不改數據，而是建一個情境，在某一項、某段時間加減一個量並寫明依據；平衡表可在基準和情境之間對照。
  - 庫存對比前五年同期的區間；庫存與月差的線性關係（給出樣本數、R²、當前偏離）。
  - 庫存偏離、表觀需求、同比、可用天數、機構口徑對照等指標。
- **煉廠盈利**：單品裂解（美國、西北歐、新加坡）、中國原油到廠成本和化工價差，以及 5 個整廠毛利模型：
  新加坡複雜型 / 簡單型、西北歐複雜型、山東燃料型、中國煉化一體化。
  中國的兩個模型按含稅口徑計算（增值稅、消費稅、附加）。
- **煉廠開工與檢修**：美國開工率、停掉的產能（可運行產能 − 總投入量）和美灣開工率（EIA 周報），
  全球停工量（諮詢機構，Excel 導入）、山東地煉和主營煉廠開工率（國內資訊商，Excel 導入）；和五年同期或去年同期比，進入綜合信號。
  國內資訊商導出的簡體表頭能直接認出（別名比對時繁簡不分）。
- **毛利拆解與試算**：每個模型可以看逐項加減、產品明細，並臨時改收率、成本、價格重算，不會保存。
- **地緣事件**：事件庫（類別、地區、狀態、對油價的方向判斷）；頁面上有金十的原油快訊流，點一下交給大模型抽成事件草稿；套用預案把事件變成情境，它的影響就能在平衡表和推演裡使用；可讓大模型從新聞裡抽取事件草稿，由你確認。每個事件可以填**機率**和**風險溢價**，頁面上顯示它發生時和按機率折算後對價格的影響，推演頁一鍵把事件同步成分支（各事件按互斥近似，剩下的機率歸基準）。
- **推演**：
  - 方向信號：四個模組各自一個 −1 到 +1 的分數，逐個信號列出依據。
  - 價格推演：設幾個情境分支和機率，得到各分支在 1 周 / 1 個月 / 3 個月的價格中樞與區間，以及機率加權價。公式全部攤開。
  - 統計模型：區間可用歷史波動率或 EWMA（近期波動權重更高）；漂移可選公允價值模型，或統計漂移模型（價格動量）。
    回測頁並排比較兩種波動率的區間（覆蓋率、評分），並檢驗統計漂移模型；**統計漂移模型要在最近一次回測裡讓 1 個月的誤差顯著變小，推演頁才允許選用**。
- **資金與宏觀**：管理基金（商品投機基金）在 WTI、Brent 上的多頭、空頭、淨多頭，以及淨多頭佔總持倉的「擁擠度」。WTI 來自 CFTC 每周的公開持倉報告，自動取數（不需要密鑰）；Brent 來自 ICE，目前 Excel 導入。擁擠度作為逆向信號進入推演（處在高位偏利空），方向是否成立看推演頁的「歷史表現」。另有匯率（歐元、日元、離岸人民幣）、黃金和油金比（金十報價）。
- **期貨曲線**：Brent、WTI、迪拜掉期、上海原油等 M1–M12 整條曲線，對比 1 周前和 1 個月前，標出近強遠弱 / 近弱遠強、M1 − M12 和蝶式（M1 − 2×M6 + M12）。曲線形態也作為指標（M1−M6、M1−M12、M6−M12、蝶式）可以看走勢和追溯。缺的月份留空，不插值。
- **期貨換月**：按交易所規則推算每天的 M1 是哪個合約（例如 M1 = 2026-12）。日變化、5 日 / 20 日變化按同一組合約對比，推演的波動率和回測收益用換月調整後的價格，換月當天兩個合約之間的價差不再當成漲跌；走勢圖上用豎虛線標出換月日。
- **基本面公允價值**：按曲線結構和庫存估算價格「應該」在哪、現在偏離多少、偏離通常多快消退，並拆出每個因子的貢獻。推演可以選擇把「預計消退的偏離」作為漂移計入。模型解釋力不足或偏離不回歸時，明說原因並不給漂移。
- **財經日曆**（金十）：之後四周的數據和事件（EIA、OPEC+、美聯儲、非農等），帶前值、市場預期和實際值。公佈時把當時的預期凍結下來，EIA / API 庫存的「實際 − 預期」記成序列和信號（從接入那天起積累，金十的日曆接口不給歷史）。
- **觀點覆盤**：記下自己的判斷（期限、方向、目標區間、把握、理由），系統同時記下當時的價格、波動率和系統信號；到期自動評分（方向用換月調整後的收益、按當時波動率劃定「沒怎麼動」），統計命中率、區間命中、把握是否校準（Brier），並按理由分類，和系統信號、「一直看多」對照。記下後不能改，只能在到期前撤銷。
- **回測**：拿歷史檢驗方向信號和推演的價格區間。每個信號給出命中率（並和「一直看多 / 看空」比）、IC、有效樣本數和是否顯著；推演區間給出實際覆蓋率。
- **報告**：一鍵生成日報 / 周報 / 月報，是那一刻的快照；可下載 Markdown、列印成 PDF；可讓大模型加一段解讀（解讀裡的數字會和正文逐個核對）。
- **問答**：用自然語言提問（「美國原油庫存比五年均值高還是低」「如果 OPEC 少供應 1 百萬桶會怎樣」）。大模型只能調用系統的查詢工具取數，回答裡的數字逐個核對，取數過程可以展開查看。問答只能查詢和試算，不能改數據。
- 每個指標顯示日 / 5 日 / 20 日變化和一年分位；任何結果都能逐層追溯到原始文件的格子和當時生效的參數。

**後台**

- **數據導入**：Excel（.xlsx、舊版 .xls）/ CSV，不要求固定模板，自動識別版式和表頭；合併儲存格的表頭（例如「Brent」橫跨 M1–M12）會展開到每一列，簡體表頭也能認出。
- **序列**：字典、走勢、手動錄入、修訂歷史。
- **參數**：所有收率、稅率、換算係數、成本，帶生效日期和完整版本記錄；標記是否已核對。
- **指標、數據源、日誌**。

**底層保證**

- 公式做量綱檢查，單位對不上的配置載入不了。
- 參數按生效日期取值；數據修訂完整留檔；可還原任意時點當時看到的數據。
- 缺數據或缺參數的指標如實顯示缺什麼，不估算。樣本不足的統計關係不擬合。
- 未來期間的值算預測，不會被當成「最新值」。
- 現貨絕對價按各油種的計價期取基準：官價用裝船月的阿曼/迪拜均價，中東現貨用裝船月的迪拜掉期，
  美國現貨用交易月對應交割月的 WTI（規則見 `config/indicators/spread.yaml` 開頭）。
  **官價要記在它適用的裝船月 1 日**（12 月裝船 → 2026-12-01），不是公布日；日期不對的數據入庫時會被拒絕。

## 啟動

需要先安裝 [Python 3.11 或更新版本](https://www.python.org/downloads/)（Windows 安裝時勾選「Add python.exe to PATH」）。

**雙擊啟動**

| 系統 | 雙擊這個文件 |
|---|---|
| Windows | `start-windows.bat` |
| Mac | `start-mac.command` |

第一次會自動安裝依賴（需要聯網，約一兩分鐘），之後直接啟動前台和後台，並在瀏覽器裡打開前台。彈出的窗口要保持開著，關掉兩個站點就都停了。

Mac 第一次雙擊如果被系統攔住，在文件上按右鍵選「打開」，再確認一次即可。

**時間顯示**：頁面右上角可以切換北京時間、洛杉磯時間（自動處理夏令時）、UTC，每個表頭都標明當前按哪個時區顯示，選擇記在瀏覽器裡。數據庫裡一律存 UTC。
定時任務的執行時間仍按 `config/schedule.yaml` 的 `timezone`（預設北京時間）來寫。

**更新到最新版本**：雙擊 `update-mac.command`（Windows 是 `update-windows.bat`）。它從 GitHub 拉最新代碼、列出這次更新了什麼，
依賴有變化時自動重新安裝，然後啟動。需要項目是用 `git clone` 下載的。

更新**不會**動到這些，不用重新設定：

| 內容 | 位置 |
|---|---|
| 數據、導入的原始文件、備份 | 項目裡的 `data/`（不在 git 裡） |
| 密鑰（API key 等） | `~/.crudelab/secrets.env`（在項目文件夾之外） |
| 這台機器自己的設定（備份放哪、登錄開關等） | `~/.crudelab/local.env`（在項目文件夾之外），用 `crudelab local set` 管理 |
| 大模型選哪個型號、思考模式、各種開關 | 數據庫（`data/` 裡），在後台頁面上改 |

所以這台機器自己的設定不要直接改倉庫裡的 `config/` 文件，改用 `crudelab local set`：倉庫裡的文件被改過時，更新腳本會停下來提示，
避免覆蓋你的修改或卡在衝突裡。`crudelab local list` 列出所有可以這樣設的項目。

**手動啟動**（雙擊不成功時，或在 Linux 上）

```bash
python3 -m venv .venv
```

```bash
.venv/bin/pip install -e ".[dev]"
```

```bash
.venv/bin/crudelab serve --open
```

Windows 把 `.venv/bin/` 換成 `.venv\Scripts\`。

只啟動其中一個站點（分開部署時用）：`crudelab serve --site front` 或 `crudelab serve --site admin`。端口用 `--port`（前台）和 `--admin-port`（後台）指定。
兩個站點互相連結用的對外地址由 `CRUDELAB_FRONT_URL`、`CRUDELAB_ADMIN_URL` 兩個環境變量指定，本機運行不用設。

### 用假數據試一遍

```bash
.venv/bin/crudelab make-sample sample.xlsx
```

在「數據導入」上傳 `sample.xlsx`，數據源選「演示用假數據」。數字是隨機生成的，不是行情。試完後清除：

```bash
.venv/bin/crudelab purge-source demo --yes
```

## 回測

在前台的「回測」頁點「開始回測」，或在命令行：

```bash
.venv/bin/crudelab backtest
```

怎麼讀結果：
- **命中率要和「上漲比例」比。** 如果這段時間油價 60% 的日子在漲，「一直看多」就有 60% 的命中率，信號要高出它才有價值。頁面上直接給出高出多少。
- **看「有效樣本」和「顯著」。** 每天評估、看一個月後的收益時，相鄰的樣本高度重疊，真正獨立的樣本只有約二十分之一。樣本不足或不顯著的結果不要當結論用。
- **「近似」的信號** 用到了月度數據，回測時用的是今天看到的修訂後數值，結果可能偏樂觀。
  機構預測（EIA 短期能源展望、IEA、OPEC）按報告期保存：補錄歷史報告時在導入頁填「報告發佈日期」
  （命令行 `crudelab import 文件 --vintage 2025-03-11`），回測就按每個日期當時已發佈的那一期算，標為「按期還原」，不再是近似。
  EIA 每天取數時自動記錄，數字變了才記新的一期；接入之前的舊數據沒有期號，那段時間仍是近似。
- **價格區間的覆蓋率** 理想約 68%。明顯偏低說明推演的區間太窄。

兩種模式：
- **按數據日期**（預設）：用於回測導入的歷史。假設每個數據在它的日期加上發佈延遲（`config/backtest.yaml`）那天就已知道。
- **按入庫時間**：只用當時已經入庫的數據，完全沒有偷看。要等系統持續收集一段時間後才有意義。

地緣模組不參與回測（事件判斷沒有歷史版本），推演的情境分支也無法回測（那是人的假設）。

公允價值模型也在回測裡：一是「價格高於公允價值時之後是否下跌」，二是「加了漂移後，推演中樞的誤差比不加時少了多少」。
**在決定讓推演使用基本面回歸之前，先看這一項是否為正且顯著。**

關係模型（供需頁的「庫存與月差」等）也做樣本外檢驗：每個評估日只用當時已知的樣本擬合，再看之後的實際值。
報告它比「y 等於窗口均值」「y 不變」兩個簡單規則好多少、y 偏離擬合值之後會不會回歸，以及每次重擬合的斜率方向是否一致。
**比兩個簡單規則都差、或斜率方向經常變的關係，頁面上的「偏高 / 偏低」不要當結論用。**

**權重校準**：回測按每個信號之後 1 個月的預測力（IC）給出建議權重：顯著有效的按 IC 給權重，
不顯著或方向相反的建議為 0（方向相反的只提示核對，不自動翻轉），樣本不足的保留現在的權重；模組權重同理。
建議值用了全部樣本，所以同時做**逐步前推檢驗**：每月初只用當時已經實現的收益重算權重、用到下個月，
再和現在的權重比。只有校準後更好時，後台「參數」頁才能一鍵採用（今天起生效，版本說明記下依據）。
信號和模組的權重都是帶生效日期的參數，回測按每個日期當時生效的權重合成，結果可以重現。
回測頁還會標出輸入「有趨勢」的信號，可在信號配置裡改成 `detrend: linear`（和趨勢線比，不是和均值比）。

## 定時任務

`crudelab serve` 啟動時會一併運行調度器（雙擊啟動也一樣），按 `config/schedule.yaml` 裡的安排自動執行：

| 預設任務 | 時間（北京時間） | 做什麼 |
|---|---|---|
| 導入收件夾 | 每 10 分鐘 | 把 `data/inbox/` 裡的 Excel / CSV 導入，完成的移到 `done/`，出錯的移到 `failed/` |
| 取 EIA 數據 | 每天 07:30 | 從 EIA 接口取數；沒設密鑰時只記「跳過」 |
| 取 CFTC 持倉 | 周六、周日 08:10 | CFTC 周五發佈的持倉報告（數據截至周二） |
| 檢查數據斷更 | 周一至周五 09:15 | 有序列超過期限沒更新時記為「有斷更」，並發通知 |
| 生成日報 | 周一至周五 18:30 | |
| 生成周報 | 每周五 19:00 | |
| 生成月報 | 每月 1 號 09:00 | 預設停用 |
| 每日備份 | 每天 02:30 | 備份數據庫、配置和原始文件並校驗，清理舊的定時備份。見「備份與恢復」 |

**收件夾的用法**：整理數據的同事把文件放進 `data/inbox/`（第一次啟動後自動建立），十分鐘內自動入庫。
自動導入只入庫能認出來的列；有認不出的列時，任務結果裡會提示，到後台「數據導入」頁手動上傳一次並指定對應，之後同樣的表頭就能自動識別。

在後台的「定時任務」頁可以看每個任務下次什麼時候跑、最近的結果和完整的執行記錄，也可以點「立即運行」。
改時間、加任務，直接改 `config/schedule.yaml`，幾秒內生效。

**開關**：「定時任務」頁上每個任務有自己的開關，另有一個「自動運行總開關」。關掉的任務不會自動執行，但仍可以手動運行。
配置文件裡的 `enabled` 只是預設值；在頁面上點過之後，以頁面為準。

### 數據斷更提醒

任務報錯有通知，但數據**悄悄停更**不會報錯：同事幾天沒往收件夾放文件、某個接口一直沒有新數據，任務每次都只是「跳過」。
斷更檢查專門抓這種情況：每個工作日早上逐條序列看有沒有超過期限沒更新，有的話通過下面的失敗通知發出。

| 頻率 | 預設期限 | 怎麼算 |
|---|---|---|
| 日度 | 3 個工作日 | 最新數據的日期離今天多遠，周末和這條序列所在市場的假期不算 |
| 周度 | 14 天 | 同上，按日曆天。EIA 周報正常最多隔 13 天左右 |
| 月度 | 40 天 | 最近一次收到新數據的時間。月度數據帶著未來的預測期，看日期永遠不會斷更 |
| 季度 | 45 天 | 同上 |

工作日按交易日曆算（`config/calendars.yaml`）：美國（CME）、歐洲（ICE）的假期按規則自動推出；
中國的長假每年由國務院公布，要逐年登記。**每年 11 月前後公布下一年安排後，把日期補進去**；
`crudelab check` 在缺了今年、或 12 月還沒有明年時會提醒。期貨換月的最後交易日也按同一份日曆算。

- 只檢查**有過數據**的序列，不會為你從沒導入過的序列報警。
- 斷更的序列會在前台總覽頂部提示（看研究結果的人能知道哪些數字可能是舊的），後台「序列」頁有「更新狀態」一列和「只看斷更的」篩選。
- 規則在 `config/freshness.yaml`：可以把關鍵序列列進 `required`（從沒有過數據也報）、把不關心的列進 `ignore`、給個別序列單獨設期限。
- 已知的誤報：中國市場的長假（國慶、春節）會讓國內期貨和現貨序列被標成斷更。需要的話給這些序列設更長的期限。

### 失敗通知

定時任務失敗時可以發到群裡或郵箱。規則：剛失敗時發一條；持續失敗每 6 小時提醒一次；恢復時再發一條。手動運行的不發。

不配置任何渠道也有站內提醒：有任務最近一次執行失敗時，後台導覽列的「定時任務」上會出現紅點。

配置一個渠道只要保存它的地址（輸入不回顯）。以企業微信為例，在群裡添加一個「群機器人」，複製它的 Webhook 地址，然後：

```bash
.venv/bin/crudelab secret set NOTIFY_WECOM_WEBHOOK
```

| 渠道 | 保存地址的密鑰名 | 備註 |
|---|---|---|
| 企業微信群機器人 | `NOTIFY_WECOM_WEBHOOK` | |
| 釘釘群機器人 | `NOTIFY_DINGTALK_WEBHOOK` | 機器人的安全設置選「自定義關鍵詞」，關鍵詞填 `crudelab` |
| 飛書群機器人 | `NOTIFY_FEISHU_WEBHOOK` | |
| Slack | `NOTIFY_SLACK_WEBHOOK` | 要先在 `config/notifications.yaml` 加一個 `type: slack` 的渠道 |
| 自定義地址 | `NOTIFY_WEBHOOK_URL` | 同上，`type: webhook`；收到一個 JSON |
| 郵件 | `SMTP_PASSWORD` | 郵箱服務器等設定寫在 `config/notifications.yaml`，裡面有示例 |

保存後到「定時任務」頁點該渠道的「發送測試」，確認群裡收到。每個渠道有自己的開關，另有一個「通知總開關」。
**群機器人的地址等同於密碼**：拿到它的人就能往你的群裡發消息，所以和 API key 一樣保管，不要貼到別處。

要知道的行為：
- **程序開著才會執行。** 電腦關機或窗口關掉期間到點的任務不會跑；重新啟動後，12 小時內錯過的按時刻執行的任務會補跑一次。
- **失敗自動重試。** 取數類任務失敗後隔一段時間自動重試（EIA、CFTC、金十報價、財經日曆、備份，次數和間隔在 `schedule.yaml`）。
  還會重試的那次顯示「失敗，待重試」，不發通知；全部重試都失敗才算失敗並通知。重試成功不會發「已恢復」。
  程序在等重試時被關掉、到了下一次執行時間，掛著的那次定為失敗並通知，不會一直懸著。
- **報告等數據導入完再生成。** 日報、周報設了 `after: [IMPORT_INBOX, PULL_EIA]`：到點後等收件夾那一輪導完、當天的 EIA 取完
  （包括重試）再生成，最多等 2 小時；等不到就照常生成，並在結果裡註明哪個沒完成。依賴失敗了也照常生成並註明。
- 生成報告時如果數據還沒更新，報告就是舊數據的快照。日報的時間請排在數據導入之後。
- 通知只在程序運行時才發得出來：整個程序掛掉或電腦關機時，沒有人會通知你。
- 斷更檢查記成「失敗」是為了借用通知的機制，頁面上顯示為「有斷更」，不是程序出錯。
- 命令行：`crudelab run-job` 列出任務，`crudelab run-job 代碼` 立即運行，`crudelab scheduler` 單獨運行調度器，`crudelab serve --no-scheduler` 不帶調度器啟動。

## 金十數據

財經日曆（含市場預期）、原油快訊、匯率和黃金等報價來自金十的 MCP 接口。接入：

1. 在你的電腦上保存 token（輸入不顯示，只存在 `~/.crudelab/secrets.env`）：

   ```bash
   .venv/bin/crudelab secret set JIN10_TOKEN
   ```

2. 檢測：列出工具、品種代碼、日曆和快訊的真實樣子（輸出裡沒有 token，可以發給負責平台的人核對）：

   ```bash
   .venv/bin/crudelab jin10 probe
   ```

3. 之後定時任務「同步財經日曆」每 2 小時、「同步原油快訊」每 10 分鐘同步一次；`crudelab jin10 usage` 看今天各工具用了幾次。
   快訊只收錄命中原油關鍵詞的（`config/jin10.yaml`），在「地緣事件」頁顯示，點「抽成草稿」才交給大模型，草稿要人確認。快訊保留 90 天。
4. 報價（匯率、黃金、金十的原油報價）每個紐約交易日記一個收盤價，品種在 `config/master/series/macro.yaml` 用 `jin10: 代碼` 登記。
   口徑：**紐約時間 16:59 那根 1 分鐘 K 線的收盤價**（金十 `get_kline` 的 `time` 是 Unix 秒，回傳截止到那一刻的 K 線）。
   日期是紐約交易日，和 EIA、CME 對齊；假期沒有 K 線就不記。
   金十的 UKOIL / USOIL 是它匯總的現貨報價，不是交易所結算價，存成單獨的序列，不混進 Brent / WTI 期貨。
   金十沒有美元指數和美債收益率，以後從其他來源接。

   **歷史補不了**：金十只保存最近 1 個交易日的分鐘線（2026-11 實測，`crudelab jin10 probe` 會量保存深度）。
   所以這些序列從接上金十那天起才開始積累。定時任務每 3 小時試一次（已取到的日子不再調用），
   只要平台每天開著一段時間就不會缺；連續一天多沒開，那幾天就永久缺了。要不缺數，平台得放在一直開著的機器上（#31 部署）。
   `crudelab jin10 backfill --days N` 仍然可以補最近能取到的幾天：從最近一天往前補，連續 5 個交易日取不到就停。
   更早的歷史要從其他來源導入（例如路透 / LSEG 導出），口徑不同的要存成單獨的序列，不要混進金十的序列。

簡繁體：金十的內容和搜索都是簡體，所以 `config/jin10.yaml` 裡的快訊關鍵詞和日曆規則要寫簡體。
打不出簡體也沒關係：照常寫繁體，運行 `crudelab check`，它會指出哪些寫成了繁體並給出簡體寫法，複製過去即可。
兩岸叫法不同的詞（例如 日圓 → 日元）在同一個文件的 `term_overrides` 裡登記，兩邊都可以寫繁體。

額度：對方每個工具每天 1500 次，`config/jin10.yaml` 再設一個 1000 次的上限，超過就不發請求。
日曆項目怎麼換算成序列（例如 EIA 原油庫存，万桶 → 千桶）也在 `config/jin10.yaml`；標題寫法要用 probe 的輸出核對。

## 從路透（LSEG Workspace）取數

在裝了 Workspace（或舊版 Eikon）的那台電腦上運行 `scripts/lseg_export.py`，它按 RIC 取歷史行情，寫成 CSV，
再交給平台導入（放進 `data/inbox/` 或在後台「數據導入」頁上傳，數據源選「路透（Excel 整理）」）。
Workspace 的接口只能在它自己那台電腦上調用，所以用「在那台電腦上導出文件」的方式，不需要打通兩台機器的網絡。

那台電腦上需要：

1. Workspace 已經打開並登錄。
2. Python 3.9 以上，並安裝 LSEG 的庫（`pip install lseg-data`；舊環境裡已有 `refinitiv-data` 或 `eikon` 也能用）。
3. 一個 App Key：在 Workspace 裡搜索「APPKEY」打開 App Key Generator 生成。**運行時輸入，不要寫進任何文件**；
   要定時運行時用環境變量 `LSEG_APP_KEY`。
4. 把 `scripts/lseg_export.py` 和 `scripts/lseg_rics.txt` 兩個文件複製到同一個文件夾。

先檢測能不能取數（只取 LCOc1 最近兩周）：

```bash
python lseg_export.py probe
```

能取數後導出（預設最近約三年；每天更新可以加 `--days 10`）：

```bash
python lseg_export.py export
```

`scripts/lseg_rics.txt` 由配置生成（`crudelab lseg-rics --output scripts/lseg_rics.txt`）：有 RIC 的序列一行一條，
還不知道 RIC 的列在後面。要補 RIC，在 `config/master/series/` 裡給序列的 `aliases` 加上，再重新生成。
現貨評估價（Platts、Argus）在路透上通常要另外訂閱，以及確認授權是否允許存進自建系統（待辦 #5）。

## 密鑰

數據源和大模型的 API key、數據庫連接串，統一這樣保管：

```bash
.venv/bin/crudelab secret set EIA_API_KEY
```

會提示你輸入，輸入時不顯示。密鑰存在 `~/.crudelab/secrets.env`：在項目文件夾之外，只有你本人能讀。
**每台機器只需要設一次**：更新代碼（`update-mac.command` 或 `git pull`）、甚至刪掉項目重新下載，都不會動到它。

```bash
.venv/bin/crudelab secret list
```

列出每個密鑰設了沒有、來自哪裡，任何時候都不顯示內容。移除用 `crudelab secret unset 名稱`。改完不用重啟。

請遵守：
- **不要**把密鑰寫進 `config/`、代碼、README、聊天或郵件，也不要用 `export 名稱=密鑰` 這種會留在終端歷史裡的方式。
- **不要**把 `~/.crudelab/` 複製進項目文件夾或隨代碼一起打包。
- 懷疑洩漏時，先到供應商後台**作廢並重發**，再換上新的。只從文件裡刪掉沒有用。
- 申請密鑰時能設額度上限、IP 限制的都設上。

服務器上可以改用環境變量注入（由平台的密鑰管理提供），環境變量優先於密鑰文件。
系統這一側的防護（錯誤訊息和日誌自動遮蔽、CI 掃描等）見 [docs/architecture.md](docs/architecture.md) 的「密鑰」一節。

## 登錄（預設關閉）

本機自己用不需要登錄，所以預設是關的：不用密碼，操作者一律記為 `local`。
**把站點開放給別人或放到服務器之前，必須先開啟。**

三種角色：

| 角色 | 前台查看 | 前台建情境、事件、推演、報告、問答 | 後台 |
|---|---|---|---|
| 只讀 `viewer` | ✓ | | |
| 研究員 `analyst` | ✓ | ✓ | |
| 管理員 `admin` | ✓ | ✓ | ✓ |

只讀帳號在前台看不到新建、保存這類按鈕；表格裡可就地修改的值（例如事件狀態、分支機率）照樣顯示，但不能改。真正的權限把關在服務器。

開啟步驟：

1. 建第一個管理員（會提示輸入密碼，至少 10 個字符）：

   ```bash
   .venv/bin/crudelab user add 你的用戶名 --role admin
   ```

2. 設環境變量後啟動：

   ```bash
   export CRUDELAB_AUTH=on
   ```

   ```bash
   .venv/bin/crudelab serve
   ```

3. 其他人的帳號在後台的「帳號」頁建立，或用 `crudelab user add`。

| 環境變量 | 說明 |
|---|---|
| `CRUDELAB_AUTH` | `on` 開啟登錄。預設關閉 |
| `CRUDELAB_SESSION_HOURS` | 登錄後多久要重新登錄，預設 12 |
| `CRUDELAB_COOKIE_SECURE` | 用 https 對外服務時設為 `on`，登錄憑證就只在加密連接上發送 |

命令行的帳號管理：`crudelab user list / add / passwd / role / disable / enable`。忘記密碼時用 `passwd` 重設。

對外提供服務時還需要做的（登錄功能本身不包辦）：
- **必須用 https**，並設 `CRUDELAB_COOKIE_SECURE=on`。用 http 的話密碼和登錄憑證是明文傳輸的。
- 在前面放一個反向代理（如 Nginx）做 https 和限流。程序自帶的「連錯 5 次鎖 15 分鐘」只是基本防護。
- 後台建議不對公網開放，只允許內網或 VPN 訪問。

## 大模型（可選）

不配置也能用：事件手動錄入，報告只有系統排版的正文。配置後多三項功能：從文字抽取事件草稿、為報告寫解讀、問答。

**選哪一家、哪個型號、開不開思考模式**：後台「大模型」頁（或 `crudelab llm use`），存在數據庫裡。
後台沒選過時，才看環境變量 `CRUDELAB_LLM_PROVIDER` / `CRUDELAB_LLM_MODEL` 和 `config/llm.yaml`。

**思考模式**（只有 DeepSeek 支持）：模型先推理再回答。回覆更慢、輸出 token 多得多，費用相應增加；抽取事件和寫解讀一般不需要，
複雜的問答可以試試。開關作為請求參數明確發送（關的時候也明確發「關」，不依賴 DeepSeek 的預設值）；開啟時系統自動給回覆多留長度、延長等待時間。

**密鑰**（`DEEPSEEK_API_KEY` / `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` / `CRUDELAB_LLM_API_KEY`）**不要寫在任何文件、命令行或聊天裡**，
只用 `crudelab secret set` 保存，見下面「密鑰」一節。

### 接入 DeepSeek

1. 在 DeepSeek 開放平台建一個**專門給 crudelab 用的** API key（不要和別的程序共用：出了問題可以單獨作廢），複製下來。
2. 在你自己的電腦上，項目文件夾裡打開終端，保存密鑰（粘貼後按 Enter，輸入不會顯示，也不會進終端的歷史記錄）：

   ```bash
   .venv/bin/crudelab secret set DEEPSEEK_API_KEY
   ```

3. 打開後台「大模型」頁的「模型設定」：供應商選 DeepSeek，點「查可用的模型」（用你的密鑰向 DeepSeek 查這個密鑰能用哪些模型，
   不耗 token），從列表裡選一個，決定開不開思考模式，點「保存」。立即生效，存在數據庫裡，以後更新代碼不用重設。
   型號名以 DeepSeek 返回的列表為準：舊名字 `deepseek-chat` / `deepseek-reasoner` 已經停用，系統不再內置任何預設型號。
4. 點同一頁的「連通測試」（只發一次很短的請求），看到「連通正常」就好了。

   命令行也可以做同樣的事：`crudelab llm models` 列出能用的模型，`crudelab llm use deepseek --model 型號名 --thinking on`
   選擇（和後台是同一個設定），`crudelab llm test` 連通測試。
5. 第一次正式用時先拿一段短新聞試「抽取事件」，再試問答。

**保護措施**（`config/llm.yaml`，詳細在 `src/crudelab/llm/limits.py` 開頭）：

- 頻率和用量上限：預設每分鐘 10 次、24 小時 300 次和 150 萬 token、同時最多 2 個請求、相鄰兩次至少隔 1 秒。超過的請求不會發出去。
- 自動暫停：密鑰無效停 24 小時，餘額不足停 6 小時，觸發對方頻率限制停 10 分鐘起（連續觸發加倍），
  1 小時內被拒絕 3 次停 1 小時，連續 3 次連不上停 10 分鐘。處理好之後在後台「大模型」頁或用 `crudelab llm reset` 解除。
- 任何失敗都不自動重試。
- 每次調用只記時間、用途、用量和結果，不記內容。後台「大模型」頁可以看最近 24 小時的用量和每次調用；命令行是 `crudelab llm status`。
- 定時任務生成報告時預設不調用大模型（`schedule.yaml` 裡 `narrative: false`）。

**數據會離開你的系統**：發給大模型的是報告正文、你的問題和查到的數字、你貼的新聞。數據授權不允許發給第三方的內容，不要接大模型，
具體見 [docs/data-requirements.md](docs/data-requirements.md) 的「大模型接口」一節。

用 Claude 需要另外安裝 `pip install -e ".[anthropic]"`。想省錢時把 `model` 換成同一家更便宜的型號即可，不用改代碼。
問答一個問題要調用大模型幾次（每查一次數據一次，最多 9 次），費用和等待時間比抽取、寫解讀高。

## 使用前需要你做的

1. **核對參數。** 所有收率、加工費、稅率、換算係數都標為「待核對」。其中收率和加工費是示意性的暫定值，不能直接當結論用。在「參數」頁逐項核對或修改。
2. **錄入運費基準費率。** TD3C / TD15 / TD20 / TD25 的 Worldscale 年度基準費率和 ESPO 運費沒有預設值，需要按年錄入；否則運費、到岸成本、套利窗口共 14 個指標算不出來。
3. **核對 EIA 序列號。** 供需的 24 條序列登記了 EIA 序列號，是按記憶填的，沒有實際調用過。用 `crudelab secret set EIA_API_KEY` 存好密鑰後先取一次數，看每條是否取到、數量級是否合理。
4. **給出推演的敏感度。** 參數 `PROJ_PRICE_PER_STOCK`（全球庫存每多累積 1 百萬桶，Brent 跌多少美元/桶）是推演的核心假設，沒有預設值；不設的話，帶供需調整的分支算不出價格。推演頁會給出從歷史估計的值（OECD 庫存月度變化 vs Brent 月度漲跌）和它的可信度；可信時可以在後台參數頁一鍵採用，依據會記在版本說明裡。
5. **核對信號的方向。** `config/signals/signals.yaml` 裡每個信號的 `direction`（數值高是利多還是利空）是我按常規理解填的，請按你的看法核對。
6. **導入數據。** 各指標需要哪些序列，在指標的狀態欄和「序列」頁可以看到。

## 數據庫

預設 SQLite，文件在 `data/crudelab.db`（不進 git，備份見下一節）。

換 PostgreSQL：安裝 `pip install -e ".[postgres]"`，然後把連接串存進密鑰文件（輸入不回顯）：

```bash
.venv/bin/crudelab secret set DATABASE_URL
```

連接串的格式是 `postgresql+psycopg://用戶名:密碼@主機:5432/庫名`。本機試驗可以用倉庫裡的 `docker-compose.yml` 起一個 PostgreSQL，密碼的設法寫在那個文件的開頭。
PostgreSQL 上的建表、導入、備份和恢復已經實測過；前台後台各頁面在 PostgreSQL 上還沒有完整走過一遍。

## 備份與恢復

**備什麼**：數據庫、`config/`、`data/` 下導入時保存的原始文件和收件夾，打包成一個 `.tar.gz`，附每個文件的 SHA-256。
做完會立即完整校驗一遍（逐個文件核對校驗碼，SQLite 再做完整性檢查），不通過就刪掉並報錯。
SQLite 用在線快照，服務開著也能備份；PostgreSQL 用 `pg_dump`（要裝 PostgreSQL 客戶端），密碼經環境變量傳給它，不出現在命令行上。

**不備什麼**：密鑰。它們在 `~/.crudelab/secrets.env`，不在數據目錄；看起來像密鑰的文件名（`secrets*`、`*.env`、`*.pem`、`*.key`）
即使出現在配置或數據目錄裡也會跳過。換機器恢復後用 `crudelab secret set` 重新錄入。備份文件本身權限是只有自己可讀。

**什麼時候備份**：定時任務「每日備份」每天 02:30 做一份，失敗會走失敗通知；後台「備份」頁可以「立即備份」，命令行是 `crudelab backup`。

**放在哪**：`config/backup.yaml` 的 `directory`，預設 `data/backups/`。**這只防誤刪、防改壞，防不了硬盤壞掉。**
正式使用前，把它指到另一塊硬盤、NAS 或雲同步文件夾（例如 `directory: /Volumes/NAS/crudelab-backups`）；
也可以只對這台機器設：`crudelab local set CRUDELAB_BACKUP_DIR /Volumes/NAS/crudelab-backups`。後台「備份」頁會提示備份是不是和數據在同一塊磁盤上。

**保留多久**：定時備份保留最近 14 天每天一份、再往前 8 周每周一份、12 個月每月一份（可在 `backup.yaml` 改）。
手動備份和恢復前的自動備份不會被自動刪除。

**怎麼恢復**（只能用命令行，網頁上不提供，因為會覆蓋數據）：

1. 關掉服務。
2. 恢復：

   ```bash
   .venv/bin/crudelab restore crudelab-20261118-023000-scheduled.tar.gz --yes
   ```

   給文件名就在備份目錄裡找，也可以給完整路徑。它會先校驗備份，檢查表結構版本（更新版本程序做的備份要先升級程序），
   再把現在的數據自動備份一份（類型「恢復前自動」），然後替換數據庫、放回原始文件、升級表結構，記一條日誌。
   配置文件預設不動（它們在 git 裡），要一起恢復加 `--with-config`。
3. 重新啟動服務。在新機器上恢復的話，`crudelab secret list` 檢查密鑰。

建議每隔一段時間在另一台機器上實際恢復一次，確認備份真的能用。
