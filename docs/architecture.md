# 架構與約定

這份文檔說明系統是怎麼分層的、每一層的規矩是什麼、要擴展時改哪裡。
寫給之後維護這個項目的人，也寫給接手的其他大模型。

## 1. 總體結構

```
config/*.yaml ──校驗──▶ Config ──同步──▶ 數據庫主數據表
                          │
外部數據 ─▶ connector ─▶ ingest ─▶ observation ─────┐
後台改參數 ─────────────▶ parameter_version ────────┼─▶ IndicatorEngine ─▶ API ─▶ 頁面 / 報告 / 大模型
人的判斷 ───────────────▶ scenario / adjustment ────┘        │
        └─ event（地緣事件）─ 套用預案 ─▶ scenario       analytics / signals / projection
                                                             │
                                                      reports（快照）◀── llm（只寫文字，數字要核對）
```

| 層 | 代碼 | 職責 | 不做什麼 |
|---|---|---|---|
| 配置 | `schema.py` `config.py` `units.py` `formula.py` `refinery.py` `balance.py` | 定義「有什麼」：序列、參數、指標公式、煉廠模型、平衡表、關係模型；一次校驗完 | 不碰數據庫 |
| 接入 | `connectors/` `imports.py` | 把外部數據變成 `Obs` 數據點 | 不做計算，不直接寫庫 |
| 存儲 | `models.py` `migrations/` `ingest.py` `parameters.py` `scenarios.py` `events.py` `master.py` | 數據點、參數、情境調整的寫入、讀取、歷史 | 不懂業務含義 |
| 計算 | `indicators.py` `analytics.py` `signals.py` `projection.py` | 按公式算指標、追溯、套用情境；季節性和擬合；方向信號；價格推演 | 不寫庫（推演的設定由同文件裡的增刪函數寫） |
| 產出 | `reports.py` `llm/` | 把某一刻的狀態收成快照並排版；大模型抽取事件、寫解讀 | 不自己算數 |
| 接口 | `api/` | 把以上能力暴露成 HTTP 接口 | 不放業務邏輯 |
| 頁面 | `web/` | 展示和交互 | 不做計算（數字全部來自接口） |

依賴只能從下往上：上層可以用下層，下層不能引用上層。

### 兩個站點

接口層和頁面層各分成兩套，對應兩個獨立的應用（`api/app.py` 的 `create_app(settings, site)`）：

| | 前台 `front` | 後台 `admin` |
|---|---|---|
| 給誰用 | 做研究的人 | 管數據和參數的人 |
| 頁面 | `web/index.html` + `js/views/front/` | `web/admin.html` + `js/views/admin/` |
| 共有的接口（只讀） | 總覽、字典、序列數據、指標、參數的當前值和版本 | 同左 |
| 獨有的接口 | 煉廠、平衡表、分析、情境、事件、推演、報告、問答 | 導入、手動錄入、改參數、數據源取數、日誌、重載配置 |

規矩：
- **寫數據和改參數的接口只掛在後台。** 新增這類接口時，放進路由模組的 `admin_router`，不要放進 `router`。
- 研究者的判斷（情境、事件、推演）是在前台寫的，它們和數據分開存，不屬於「管理數據」。
- 兩個應用可以在一個進程裡各佔一個端口（`crudelab serve`），也可以是兩個進程甚至兩台機器，只要連同一個數據庫、讀同一份 `config/`。
- 因為可能是兩個進程，配置不靠互相通知來同步：每個應用自己盯著 `config/` 的文件，發現改動就重新載入（`api/deps.py` 的 `AppState`）；
  新配置有錯就沿用上一份，並在頁面頂部顯示錯誤。
- 頁面之間用完整網址互相連結（`js/site.js` 的 `adminLink`），不假設兩個站點同源。
- 登錄功能預設關閉，由 `CRUDELAB_AUTH` 開啟，見下一小節。

### 登錄與權限

`auth.py`（帳號、密碼、會話）+ `api/security.py`（訪問控制）+ `api/routes/auth.py`。

- **統一把關。** 每個 `/api` 路由在掛載時都帶上同一個 `guard` 依賴（`api/app.py`）。
  權限是按「站點 + 請求方法」判斷的，不是逐個路由標註：後台一切要管理員；前台 GET 要登錄，會改東西的請求要研究員。
  所以新增路由不需要、也不應該自己寫權限判斷。唯一要記得的是：用 POST 但不保存任何東西的試算，登記到 `READ_ONLY_POSTS`。
- **不用登錄的地址只有 `PUBLIC` 裡那幾個**（登錄、登出、查自己是誰、站點信息）。往裡加東西要非常小心。
- **操作者** 由 `get_actor` 給出：開了登錄是用戶名，沒開是 `local`。各種記錄裡的「誰做的」都來自它。
- **密碼** 用 scrypt 加鹽哈希；**會話** 是隨機令牌，庫裡只存它的 SHA-256，瀏覽器端放在 HttpOnly + SameSite=Lax 的 cookie 裡。
- **防跨站偽造**：SameSite cookie，加上寫請求的 Origin 必須和本站一致。
- 帳號只停用不刪除；停用、改密碼會立刻讓它的所有登錄失效；不允許把最後一個可用的管理員降級或停用。
- 開了登錄但沒有管理員帳號時，程序拒絕啟動。
- 沒做的：按人細分到模組的權限、單點登錄、兩步驗證、密碼過期。登錄失敗的計數在內存裡，多進程時各算各的。

## 2. 不能破壞的規矩

1. **數字只有一條計算路徑。** 所有衍生數字都是「指標」，由 `IndicatorEngine` 按 `config/` 裡的公式算。
   頁面、報告、大模型都不能自己算數。煉廠模型也不例外：它被編譯成指標。
2. **沒有就是沒有。** 輸入缺值，結果就缺值，並說明缺什麼（缺數據 / 缺參數）。不估算、不插值、不用假數頂替。
   允許的唯一例外是聲明過的「沿用」：序列的 `valid_days`、指標的 `ffill_limit`。
3. **公式裡沒有魔法數字。** 換算係數、稅率、收率都是有名字、有單位、有生效日期的參數。
4. **單位必須對得上。** 每個序列、參數、指標都有單位，公式載入時做量綱檢查。
5. **歷史不被改寫。** 數據點被改時舊值進 `observation_revision`；參數只增版本不改舊版本。
   因此任何結果都能用 `as_of` 還原「當時看到的樣子」。
6. **來源可追溯。** 每個數據點記著來自哪個數據源、哪個文件、哪個格子；原文件原樣保存在 `data/raw/`。
7. **配置是主數據的唯一來源。** 數據庫裡的主數據表只是鏡像。唯一例外是參數的數值：
   配置只提供初始值，之後以後台為準（因為數值需要生效日期和修改記錄）。
8. **表結構只通過遷移腳本改。**
9. **數據和判斷分開存。** 人的判斷（「我認為 OPEC 會多產 40 萬桶」）不改數據，而是作為情境裡的調整疊加上去，
   每條調整寫明依據。任何時候都能看「數據說什麼」和「加上判斷後是什麼」的差別。
10. **預測不冒充現狀。** 日期在今天之後的值是預測；指標的「最新值」只取已經發生的期間。
11. **大模型只處理文字，而且不直接生效。** 它抽取的事件是草稿，要人確認；它寫的解讀單獨存放、標明出處，
    其中每個數字都要能在報告正文裡找到（`llm/guard.py`），對不上的會被列出來。報告正文不經過大模型。
12. **推演把假設攤開。** 信號和價格推演的每一步都有公式、有來源：哪些來自行情，哪些是人設的（機率、敏感度、方向判斷）。
    缺任何一項輸入就留空並說明原因，不補默認值。
13. **報告是快照。** 生成後不再變化；之後數據或參數怎麼改都不影響已出的報告。

### 定時任務

`scheduler.py`（什麼時候跑）+ `jobs.py`（跑什麼、怎麼記結果），任務聲明在 `config/schedule.yaml`。

- **時間的算法是純函數**（`due_slot` / `next_slot`）：給定現在的時間，算出一個任務「最近一次該跑的時點」。
  調度器每 30 秒看一遍，哪個時點還沒被執行過就執行。沒有常駐的定時器狀態，進程重啟不影響正確性。
- **不重複執行靠數據庫**：`job_run` 表的 (任務, 時點) 唯一。執行前先插入一條記錄來「認領」，插入失敗說明別的進程已經認領了。
  所以即使不小心起了兩個調度器，同一個時點也只跑一次。
- **任務永遠不會把調度器打掉**：每次執行的異常都被接住並記成 `failed`。意料之外的異常只把類型記進結果，原文進日誌（日誌有脫敏）。
- **結果四種**：`ok`、`skipped`（沒有可做的事，不是錯誤）、`failed`、`running`。進程被殺掉留下的 `running` 在下次啟動時改成 `failed`。
- 任務順序執行，不並行。
- 操作者記為 `scheduler`。
- 調度器預設跟著後台應用跑（`crudelab serve`），也可以單獨跑（`crudelab scheduler`）。它每輪寫一次心跳，頁面據此顯示是否在運行。
- 加一種新動作：在 `jobs.py` 寫一個函數並登記到 `ACTIONS`，在 `schema.JobDef` 的 `action` 裡加上它的名字。

沒有做的：失敗後自動重試；任務之間的依賴（例如「導入完成後再出報告」，目前只能靠把時間錯開）。

### 開關

`switches.py`。後台頁面上能點的開關都存在 `switch` 表：`scheduler`（自動運行總開關）、`job:代碼`、`notify`（通知總開關）、`channel:代碼`。
沒有記錄時用配置文件裡的 `enabled`，有記錄時以表為準（和參數的做法一致：配置給預設值，後台改了以後台為準）。
開關只管「自動」：關掉的任務仍可手動運行，關掉的渠道仍可發測試。每次切換記入操作日誌。

### 通知

`notifications.py`，規則和渠道在 `config/notifications.yaml`。

- 只在調度器裡、任務執行完之後調用（`after_run`）。判斷（`decide`）和發送（`send`）分開，判斷是純邏輯。
- 發的時機：剛失敗、持續失敗超過 `repeat_hours`、恢復。「跳過」不算有結果；手動觸發的不發。
- **群機器人的地址是密鑰**，和 API key 走同一套：`credentials.KNOWN` 登記、`crudelab secret set` 保存、不進配置。
- 內容發出前過一遍脫敏；發送失敗只記狀態碼或異常類型，不記地址；地址必須是 https（本機除外）。
- 發送失敗不影響任務，也不重試。每次通知和各渠道的結果記在 `notification` 表。
- 加一種渠道：在 `schema.ChannelDef.type` 加名字，在 `notifications._payload`（或另寫一個發送函數）裡加格式，在 `WEBHOOK_CREDENTIALS` 和 `credentials.KNOWN` 登記密鑰名。

沒有做的：程序本身掛掉時的通知（需要外部監控來盯心跳）；按任務分別指定通知對象。

### 數據斷更

`freshness.py`，規則在 `config/freshness.yaml`。

- 是一個定時任務動作（`check_freshness`）：有斷更就記為 `failed`，從而原樣復用失敗通知的首次提醒、持續提醒、恢復；
  開關、紅點也都自動有。頁面和通知對這個動作換了措辭（「有斷更」「數據斷更」），免得看成程序出錯。
- 兩種量法：`observed` 看最新數據點的日期（不晚於今天）；`received` 看最近一次收到新值或修訂的時間（`observation.updated_at`）。
  帶預測期的月度、季度數據必須用後者，否則最新日期在未來，永遠不會斷更。
- 日度預設按工作日數，不考慮節假日日曆，所以長假會誤報。要精確需要交易所日曆，目前沒做。
- 只檢查有過數據的序列（`watch: has_data`），外加 `required` 裡的。「今天」按 `schedule.yaml` 的時區算。
- 同一套結果供三處使用：定時任務、`/api/freshness`（前台總覽和後台序列頁都用它）。

### 密鑰

`credentials.py` 是密鑰的唯一出入口。規矩：

- **來源只有兩個**：環境變量，或 `~/.crudelab/secrets.env`（項目之外，權限 600，別人可讀時拒絕使用）。
  不進 git、不進 `config/`、不進數據庫、不進 `data/`。
- **取密鑰只調用 `credentials.get()`**，不要自己讀 `os.environ`。新密鑰先在 `credentials.KNOWN` 登記，否則取不到，脫敏也遮不到。
- **密鑰不進任何輸出**。對外部服務的錯誤只報狀態碼和我們自己寫的說明：不轉述對方返回的原文，不打印請求網址，
  拋出時用 `from None` 切斷原始異常（EIA 的 key 在網址參數裡，原始異常的文字裡就有它）。
  connector 的錯誤用 `ConnectorError`，大模型的用 `LLMError`，兩者的訊息都必須是我們自己寫的。
- **兩層兜底**：所有日誌過 `_RedactingFilter`，所有錯誤回應過 `redact()`，把已知的密鑰值和常見樣式換成 `***`。
  兜底不是可以放心亂打印的理由。
- **倉庫側**：`.gitignore` 排除常見密鑰文件；`scripts/check_secrets.py` 由 CI 每次掃描；`tests/test_credentials.py` 給每條已知的洩漏路徑各留了一個測試。
- 可以打印的數據庫連接串用 `settings.safe_database_url`。

沒有做的：密鑰文件本身沒有加密（靠文件權限和系統的帳戶隔離保護；Windows 上沒有權限位檢查）；沒有接雲廠商的密鑰管理服務
（服務器上通過環境變量對接）；沒有自動輪換。

**數據外發**是另一個要管的出口：用大模型時，報告正文和問答查到的數據會發給供應商，清單見 `docs/data-requirements.md`。

## 3. 兩條時間軸

| | 含義 | 字段 |
|---|---|---|
| 業務時間 | 這個值說的是哪一天 | `observation.obs_date`、`parameter_version.valid_from` |
| 記錄時間 | 系統什麼時候知道的 | `created_at`、`updated_at`、`replaced_at` |

- 參數按業務時間取值：2019-04-01 起增值稅 13%，那麼算 2018 年的成本時自動用當時的稅率。
- `as_of` 按記錄時間過濾：只看那個時點之前入庫的數據點和參數版本。回測時用它避免偷看後來的修訂。

時間一律存 UTC。

**期間型數據的日期**：月度、季度、年度的值代表整個期間，一律記在期間的第一天（2026 年 9 月 → `2026-09-01`）。
周度數據記在數據源給的日期。解析規則在 `periods.py`，Excel 導入和各 connector 共用。

## 4. 命名

| 對象 | 規則 | 例子 |
|---|---|---|
| 序列 | 大寫加下劃線；連續合約以 `_M1` `_M2` 結尾 | `BRENT_M1`、`ESPO_DIFF` |
| 參數 | 大寫加下劃線；換算係數 `BBL_PER_T_*`，中國稅費 `CN_*` | `CN_VAT_RATE` |
| 指標 | 前綴表示類別 | `SPR_` 價差、`TS_` 月差、`OUT_` 絕對價、`FRT_` 運費、`CIF_` 到岸、`ARB_` 套利、`CRK_` 裂解、`QS_` 品質價差、`STK_` 庫存、`DEM_` 需求、`GLB_` 全球、`CMP_` 機構對照 |
| 煉廠模型生成的 | `RM_{模型}_…` | `RM_CN_FUEL_SD_MARGIN`、`RM_CN_FUEL_SD_Y_GASOLINE` |
| 平衡表生成的 | `BAL_{表}_…` | `BAL_GLOBAL_BALANCE`、`BAL_GLOBAL_S_OPEC` |
| 情境 | 大寫加下劃線 | `MY_VIEW` |

序列、參數、指標共用一個命名空間，不能重名。

## 5. 怎麼擴展

| 要做的事 | 改哪裡 | 要不要寫代碼 |
|---|---|---|
| 加一條序列 | `config/master/series/*.yaml` | 否 |
| 加一個指標 | `config/indicators/*.yaml` | 否 |
| 加 / 改一個參數 | `config/parameters/*.yaml` 加定義；數值在後台改 | 否 |
| 加一個煉廠模型，或改原料、產品結構 | `config/refineries/*.yaml` | 否 |
| 加一張平衡表，或改它的分項 | `config/balances/*.yaml` | 否 |
| 加一個關係模型 | `config/relations/*.yaml` | 否 |
| 加一個方向信號 | `config/signals/*.yaml` | 否 |
| 加一個事件預案 | `config/geo/playbooks.yaml` | 否 |
| 改推演的價格、期限、用哪張平衡表 | `config/projection.yaml` | 否 |
| 換一家大模型 | 環境變量，見 `llm/registry.py` | 否 |
| 接一家新的大模型 | 在 `llm/providers.py` 加一個 `LLMProvider` 子類，並在 `llm/registry.py` 登記 | 是 |
| 讓大模型多做一件事 | 在 `llm/tasks.py` 加一個函數：提示詞、輸出校驗、結果怎麼交給人確認 | 是 |
| 讓問答能查更多東西 | 在 `llm/chat.py` 加一個 `tool_*` 函數並登記到 `TOOLS`。工具必須唯讀 | 是 |
| 加 / 改一個定時任務 | `config/schedule.yaml` | 否 |
| 加 / 改通知渠道和規則 | `config/notifications.yaml` | 否 |
| 改斷更的期限、指定關鍵序列 | `config/freshness.yaml` | 否 |
| 改換月規則、修正某個合約的最後交易日 | 曲線配置的 `roll`（`overrides: {"2026-12": 2026-10-29}`） | 否 |
| 加一條期貨曲線、改月份數 | `config/master/series/*.yaml` 的 `curves`（形態指標在 `config/indicators/spread.yaml` 的「曲線形態」組） | 否 |
| 換大模型、改調用上限 | `config/llm.yaml`（密鑰用 `crudelab secret set`） | 否 |
| 改備份位置、保留策略 | `config/backup.yaml`（或環境變量 `CRUDELAB_BACKUP_DIR`） | 否 |
| 加 / 改公允價值模型的因子 | `config/fair_value.yaml` | 否 |
| 加一個新單位 | `config/master/units.yaml`（必要時加原子單位） | 否 |
| 加一個公式函數 | `formula.py` 的 `FUNCTIONS`，並在 `infer_unit` 說明它對單位的影響 | 是 |
| 接通一個數據源 | 見 `connectors/reserved.py` 開頭的步驟 | 是 |
| 加一個分析模組（地緣） | 指標的 `module` 填 `geo`；需要新的數據形態時加表（寫遷移） | 視情況 |
| 改表結構 | 見下 | 是 |

改完配置後運行 `crudelab check`。它會一次列出全部問題。

### 改表結構

1. 改 `models.py`。
2. 生成遷移腳本，並檢查生成的內容：

   ```bash
   alembic revision --autogenerate -m "說明這次改了什麼"
   ```

3. 跑測試。`tests/test_schema.py` 會檢查遷移腳本和模型是否一致。

程序啟動時會自動把數據庫升級到最新版本。

## 6. 情境

`IndicatorEngine(session, cfg, scenario=Scenario(…))` 在不改數據的前提下替換參數值、平移序列或指標，然後照常計算。
`Scenario` 有三種內容：`parameters`（換參數值）、`shifts`（全時段加減）、`ranged`（分時段加減）。

情境有兩種用法：

- **臨時試算**：請求裡帶上假設，算完即棄。煉廠頁面的「試算」是這種。
- **保存的情境**：`scenario` 和 `adjustment` 兩張表，由 `scenarios.py` 讀寫。每條調整 = 目標（序列或指標）+ 時段 + 加減量 + 依據。
  幾乎所有讀數的接口都接受 `?scenario=代碼`，所以任何指標都能在某個情境下查看。供需頁面的情境調整是這種。

調整加在序列上，會傳到所有用到它的指標；加在指標上，只影響該指標及其下游。
第四期的地緣事件會落成保存的情境（事件 → 一組帶時段的調整），推演引擎在多個情境之間比較。

## 7. 從事件到價格的鏈條

```
地緣事件（events）──方向判斷──▶ 地緣信號
     │ 套用預案
     ▼
情境（scenario + adjustment）──▶ 平衡表在情境下的變化
     │ 作為推演的一個分支                │
     ▼                                   ▼
推演分支：機率、直接價格調整 ──▶ 中樞 = 當前價格 − 敏感度 × 平衡變化 + 直接價格調整
                                 區間 = ± 當前價格 × 日波動率 × √交易日數
                                 機率加權價 = Σ 機率 × 中樞
```

- **信號**（`signals.py`）回答「現在處在歷史什麼位置」：z 分數折成 −1 到 +1，模組內加權、模組間加權。它不進入價格計算。
- **推演**（`projection.py`）回答「如果這些情境按這些機率發生，價格大致在哪」。
- 兩者都不是預測模型。統計或機器學習的預測模型以後可以作為推演的一個輸入接進來（例如給基準分支一個漂移），接口已經留好：
  推演的每一項都是獨立的加數。

### 問答

`llm/chat.py`。每一步讓模型輸出一個 JSON：要麼調一個工具，要麼給出回答；最多 8 步。
沒有用任何一家專有的「工具調用」格式，所以三家通用。工具全部唯讀，「如果…會怎樣」走 `Scenario` 臨時計算，不保存。
回答的數字核對範圍 = 使用者的問題 + 之前的對話 + 本次所有工具結果。對話歷史由頁面保存並隨請求帶上，伺服器不存。

### 期貨曲線

`curves.py`，曲線來自序列配置裡的 `curves` 模板（展開成 `{code}_M1` … `{code}_M12` 的連續合約序列）。要點：

- **對比日按 M1 自己的交易日往回數**（5、21 個），不按日曆天；某月份當天沒值時最多往前找 3 天，再沒有就留空，不插值。
- 形態：近遠月價差 = M1 − 最遠有數據的月份；絕對值小於 M1 的 0.5% 算平坦；蝶式要 M1、M6、M12 都有才算。
- 曲線形態指標（`TS_*_M1_M6`、`TS_*_M1_M12`、`TS_*_M6_M12`、`CRV_*_FLY`）是普通公式指標，可以追溯；目前**沒有**做成方向信號，因為還沒有回測驗證。
- 每個點標出當天對應的具體合約；對比日以來換過月時 `rolls_since` 標出次數。換月處理見下一節。

### 讀數據的性能

每個頁面請求都要建一個 `IndicatorEngine`，它需要全部數據點。兩層緩存：

- **跨請求**（`ingest.load_points_cached`）：數據沒變就直接用上一次讀出的表。是否變了看指紋：數據點條數、
  最新修改時間、最大編號、修訂記錄條數、各數據源的優先級；任何導入、改值、刪除都會讓緩存失效。
  緩存失效時只讓一個請求去讀，其他請求等它讀完（頁面一次發好幾個請求，同時讀全表會互相拖慢十幾倍）。
  按時點還原（`as_of`）不走這個緩存。`tests/test_audit_fixes.py` 驗證了新增、改值、優先級、刪除都能立即看到。
- **請求內**（`IndicatorEngine._raw`）：數據點只按序列分組一次；固定合約視圖按錨定日共用。

### 期貨換月

`contracts.py`，規則在曲線配置的 `roll` 字段，詳細說明在文件開頭。數據裡仍然只存連續合約（數據商給的就是 M1、M2…），
具體合約由規則推出，不另存一份。要點：

- **合約日曆**：`last_trading_day` 按規則算每個合約月份的最後交易日（只認周一到周五，假期用 `overrides` 修正）；
  最後交易日當天仍是 M1，第二天換。`front_ordinal` 給出每天的 M1 是哪個合約，Mn = M1 + n − 1。
- **變化量按同一組合約**：`IndicatorEngine.summary` 的日 / 5 日 / 20 日變化，對依賴期貨曲線的指標用
  `pinned(錨定日)` 視圖算：過去每一天的 Mn 換成錨定日那個 Mn 合約當天的價格（即 M(n + 換月次數)）。
  取不到（例如 M12 跨換月要 M13）時退回直接相減，在 `chg_unadjusted` 裡標出，頁面上打 †。
- **收益按換月調整**：`chained_returns` / `adjusted_prices`。換月日的收益 = log(今天的 Mn / 昨天同一合約)。
  推演的波動率、回測的前向收益、波動區間、公允價值的回測收益都用它。最新值等於原始價格。
- **原始值不改**：走勢圖、指標的歷史值、追溯都是連續合約的原始值，換月日在走勢圖上畫豎虛線。
- 規則的 `verified: false` 表示還沒和數據商實際換月日核對；迪拜掉期 M1 的定義在不同數據商之間不一致，尤其要核對。
- `tests/test_contracts.py` 用「每個合約價格固定不變」的數據驗證：連續合約在換月日跳動，但同一合約的變化和調整後收益都是 0。

### 備份與恢復

`backup.py`，設定在 `config/backup.yaml`，格式和流程寫在文件開頭。要點：

- **一致**：SQLite 用在線備份接口做快照；其他文件先複製到臨時目錄，之後只讀副本，打包期間文件被改動也不會造成清單和內容不符。
- **原子**：寫成 `.partial` 再改名，備份目錄裡不會出現半份備份；做完立即完整校驗，不通過就刪掉。
- **可校驗**：`manifest.json` 是第一個成員，記每個文件的大小和 SHA-256；校驗時多出、缺少、被改的文件和不安全的路徑都會被拒絕。
- **不含密鑰**：密鑰文件不在數據目錄；像密鑰的文件名一律跳過；PostgreSQL 的密碼經環境變量交給 `pg_dump`，錯誤輸出先脫敏。
- **恢復有保護**：只能用命令行；服務開著（調度器心跳兩分鐘內）時拒絕；先做一份 pre-restore 備份；
  表結構版本不認識（更新版本程序做的備份）時拒絕；恢復後升級表結構並記日誌。
- `tests/test_backup.py` 覆蓋：內容與排除、篡改 / 缺失 / 截斷 / 路徑穿越、SQLite 恢復往返、安全檢查、保留策略、定時任務、接口；
  設了 `CRUDELAB_TEST_PG_URL` 時再跑一遍 PostgreSQL 的備份恢復往返。

### 基本面公允價值

`fair_value.py`，模型在 `config/fair_value.yaml`。詳細算法在文件開頭。要點：

- **每個日期只用它之前的數據擬合**（滾動窗口最小二乘），所以整條歷史曲線都是當時就能算出的，回測和實時用同一個 `fit_at`。
  `tests/test_fair_value.py` 驗證了改動未來的數據不影響過去的擬合。
- **可解釋**：公允價值 = 窗口均值水平 + 各因子貢獻（係數 × 因子相對窗口均值的偏離）。
- **漂移**：從殘差的 AR(1) 係數 φ 得到半衰期，h 個交易日預計消退 (1 − φʰ) 的偏離。假設因子在期限內不變。
- **不硬給**：R² 低於門檻或 φ 不在 (0, 1) 時 status 為 weak，展示但不給漂移；推演裡說明原因。
- 推演是否使用漂移是每個推演自己的選擇（`projection.drift_model`），預設不用。
- 回測裡評估兩件事：偏離作為信號；漂移相對「不加漂移」減少的中樞誤差（`evaluate_drift`，按有效樣本算顯著性）。

### 回測

`backtest.py`，設定在 `config/backtest.yaml`，詳細說明在文件開頭。要點：

- **和實際信號完全一致**：回測裡某一天的信號分數必須等於那一天在推演頁上會看到的分數。按數據日期的模式是向量化的
  （`rolling_scores` 用和 `signals.data_signal` 一樣的窗口定義），按入庫時間的模式直接逐日調用 `signals.data_signal`。
  `tests/test_backtest.py` 對兩種模式都做了逐日比對。改信號的算法時，兩邊必須一起改，這個測試會擋住不一致。
- **不偷看未來**：按數據日期時扣發佈延遲（`as_available`）；按入庫時間時用 `as_of`。之後的收益一律用今天的價格。
- **誠實的統計**：有效樣本 = n × min(1, 間隔 / 期限)；顯著性、命中率的置信區間都按它算；命中率和同期上漲比例對照。
- 結果存在 `backtest_run`，是快照。接口在前台（研究功能）；後台線程執行，頁面輪詢。
- 加新的被評估對象（例如公允價值模型）：在 `run()` 裡產出一條按評估日索引的分數序列，交給 `evaluate()`。

## 8. 已知的簡化

這些地方目前是近似處理，用到時要心裡有數：

- 方向信號在最新值太舊時不出分（日度 10 天、周度 21 天、月度 70 天、季度 200 天，`signals.STALE_DAYS`），回測用同一規則。
  這個期限是固定的，不跟 `freshness.yaml` 的斷更規則聯動。
- 換月日按規則推算，只認周一到周五；和數據商實際換月不一致的那一兩天（交易所假期、數據商提前換月）仍會有跳動，
  發現後在 `overrides` 裡改。公式裡的 `diff` / `lag` 函數和公允價值的擬合用的是原始連續合約，不做換月調整。
- 升貼水和官價的計價期用 M1 或當日現貨近似，沒有按實際計價月份對齊。
- 原油桶噸比用一個通用係數，沒有分油種。
- 機構預測只保留最新一版的值加修訂記錄，沒有按報告期號（例如「11 月報」）存成獨立的版本；
  用 `as_of` 只能還原「系統當時錄到的值」，補錄歷史報告時還原不出當時的發佈順序。
- 全球平衡表直接用 EIA 的分項，沒有分國別自下而上搭建。
- 關係模型是簡單線性擬合，沒有做滯後、分段或穩健性處理。
- 回測的地緣模組不參與；推演只檢驗基準分支的區間；按數據日期回測用修訂後數值。
- 公允價值模型是線性的、因子只有兩個，漂移假設基本面在期限內不變；平衡敏感度仍要人給。
- 推演的敏感度是線性的，不隨期限、庫存水平變化；基準分支沒有漂移；區間用正態近似的一倍標準差。
- 信號用 z 分數，隱含假設指標圍繞均值波動；有長期趨勢的指標（例如同比）會偏。
- 地緣信號只是各事件方向判斷的加總，沒有按事件大小或機率加權。
- 大模型的三家接入都沒有用真實密鑰驗證過。
- 問答用「模型輸出 JSON」的樸素協議而不是各家原生的工具調用，通用但對弱一些的模型不夠穩；數字核對只查數字是否出現過，
  查不出「數字對但張冠李戴」（把 A 指標的值說成 B 指標）。回答下面的「依據」就是為了讓人能核對這一點。
- 每次請求都從數據庫重新讀全部數據點再計算。目前的數據量下每個頁面不到一秒；數據量再大一兩個數量級時需要加緩存。
- 含稅模型裡，產品收入低於原料成本時增值稅為負（視為進項當期全額抵扣）；加工環節的其他進項不計。
- 登錄功能預設關閉，關閉時操作者固定記為 `local`、兩個站點都不設防。
