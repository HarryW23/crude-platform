# 架構與約定

這份文檔說明系統是怎麼分層的、每一層的規矩是什麼、要擴展時改哪裡。
寫給之後維護這個項目的人，也寫給接手的其他大模型。

## 1. 總體結構

```
config/*.yaml ──校驗──▶ Config ──同步──▶ 數據庫主數據表
                          │
外部數據 ─▶ connector ─▶ ingest ─▶ observation ─────┐
後台改參數 ─────────────▶ parameter_version ────────┼─▶ IndicatorEngine ─▶ API ─▶ 頁面 / 報告 / 大模型
人的判斷 ───────────────▶ scenario / adjustment ────┘        │
                                                      analytics（季節性、擬合）
```

| 層 | 代碼 | 職責 | 不做什麼 |
|---|---|---|---|
| 配置 | `schema.py` `config.py` `units.py` `formula.py` `refinery.py` `balance.py` | 定義「有什麼」：序列、參數、指標公式、煉廠模型、平衡表、關係模型；一次校驗完 | 不碰數據庫 |
| 接入 | `connectors/` `imports.py` | 把外部數據變成 `Obs` 數據點 | 不做計算，不直接寫庫 |
| 存儲 | `models.py` `migrations/` `ingest.py` `parameters.py` `scenarios.py` `master.py` | 數據點、參數、情境調整的寫入、讀取、歷史 | 不懂業務含義 |
| 計算 | `indicators.py` `analytics.py` | 按公式算指標、追溯、套用情境；對結果做季節性和擬合 | 不寫庫 |
| 接口 | `api/` | 把以上能力暴露成 HTTP 接口 | 不放業務邏輯 |
| 頁面 | `web/` | 展示和交互 | 不做計算（數字全部來自接口） |

依賴只能從下往上：上層可以用下層，下層不能引用上層。

## 2. 不能破壞的規矩

1. **數字只有一條計算路徑。** 所有衍生數字都是「指標」，由 `IndicatorEngine` 按 `config/` 裡的公式算。
   頁面、報告、大模型都不能自己算數。煉廠模型也不例外：它被編譯成指標。
2. **沒有就是沒有。** 輸入缺值，結果就缺值，並說明缺什麼（缺數據 / 缺參數）。不估算、不插值、不用假數頂替。
   允許的唯一例外是聲明過的「沿用」：序列的 `valid_days`、指標的 `ffill_limit`。
3. **公式裡沒有魔法數字。** 換算係數、稅率、收率都是有名字、有單位、有生效日期的參數。
4. **單位必須對得上。** 每個序列、參數、指標都有單位，公式載入時做量綱檢查。
5. **歷史不被改寫。** 數據點被改時舊值進 `observation_revision`；參數只增版本不改舊版本。
   因此任何結果都能用 `as_of` 還原「當時看到的樣子」。
6. **來源可追溯。** 每個數據點記著來自哪個數據源、哪個文件、哪個格子；原文件原樣保存在 `data/raw/`。
7. **配置是主數據的唯一來源。** 數據庫裡的主數據表只是鏡像。唯一例外是參數的數值：
   配置只提供初始值，之後以後台為準（因為數值需要生效日期和修改記錄）。
8. **表結構只通過遷移腳本改。**
9. **數據和判斷分開存。** 人的判斷（「我認為 OPEC 會多產 40 萬桶」）不改數據，而是作為情境裡的調整疊加上去，
   每條調整寫明依據。任何時候都能看「數據說什麼」和「加上判斷後是什麼」的差別。
10. **預測不冒充現狀。** 日期在今天之後的值是預測；指標的「最新值」只取已經發生的期間。

## 3. 兩條時間軸

| | 含義 | 字段 |
|---|---|---|
| 業務時間 | 這個值說的是哪一天 | `observation.obs_date`、`parameter_version.valid_from` |
| 記錄時間 | 系統什麼時候知道的 | `created_at`、`updated_at`、`replaced_at` |

- 參數按業務時間取值：2019-04-01 起增值稅 13%，那麼算 2018 年的成本時自動用當時的稅率。
- `as_of` 按記錄時間過濾：只看那個時點之前入庫的數據點和參數版本。回測時用它避免偷看後來的修訂。

時間一律存 UTC。

**期間型數據的日期**：月度、季度、年度的值代表整個期間，一律記在期間的第一天（2026 年 9 月 → `2026-09-01`）。
周度數據記在數據源給的日期。解析規則在 `periods.py`，Excel 導入和各 connector 共用。

## 4. 命名

| 對象 | 規則 | 例子 |
|---|---|---|
| 序列 | 大寫加下劃線；連續合約以 `_M1` `_M2` 結尾 | `BRENT_M1`、`ESPO_DIFF` |
| 參數 | 大寫加下劃線；換算係數 `BBL_PER_T_*`，中國稅費 `CN_*` | `CN_VAT_RATE` |
| 指標 | 前綴表示類別 | `SPR_` 價差、`TS_` 月差、`OUT_` 絕對價、`FRT_` 運費、`CIF_` 到岸、`ARB_` 套利、`CRK_` 裂解、`QS_` 品質價差、`STK_` 庫存、`DEM_` 需求、`GLB_` 全球、`CMP_` 機構對照 |
| 煉廠模型生成的 | `RM_{模型}_…` | `RM_CN_FUEL_SD_MARGIN`、`RM_CN_FUEL_SD_Y_GASOLINE` |
| 平衡表生成的 | `BAL_{表}_…` | `BAL_GLOBAL_BALANCE`、`BAL_GLOBAL_S_OPEC` |
| 情境 | 大寫加下劃線 | `MY_VIEW` |

序列、參數、指標共用一個命名空間，不能重名。

## 5. 怎麼擴展

| 要做的事 | 改哪裡 | 要不要寫代碼 |
|---|---|---|
| 加一條序列 | `config/master/series/*.yaml` | 否 |
| 加一個指標 | `config/indicators/*.yaml` | 否 |
| 加 / 改一個參數 | `config/parameters/*.yaml` 加定義；數值在後台改 | 否 |
| 加一個煉廠模型，或改原料、產品結構 | `config/refineries/*.yaml` | 否 |
| 加一張平衡表，或改它的分項 | `config/balances/*.yaml` | 否 |
| 加一個關係模型 | `config/relations/*.yaml` | 否 |
| 加一個新單位 | `config/master/units.yaml`（必要時加原子單位） | 否 |
| 加一個公式函數 | `formula.py` 的 `FUNCTIONS`，並在 `infer_unit` 說明它對單位的影響 | 是 |
| 接通一個數據源 | 見 `connectors/reserved.py` 開頭的步驟 | 是 |
| 加一個分析模組（地緣） | 指標的 `module` 填 `geo`；需要新的數據形態時加表（寫遷移） | 視情況 |
| 改表結構 | 見下 | 是 |
| 接大模型 | 實現 `llm.LLMProvider`；讓它調用 `/api` 接口取數，不讓它算數 | 是 |

改完配置後運行 `crudelab check`。它會一次列出全部問題。

### 改表結構

1. 改 `models.py`。
2. 生成遷移腳本，並檢查生成的內容：

   ```bash
   alembic revision --autogenerate -m "說明這次改了什麼"
   ```

3. 跑測試。`tests/test_schema.py` 會檢查遷移腳本和模型是否一致。

程序啟動時會自動把數據庫升級到最新版本。

## 6. 情境

`IndicatorEngine(session, cfg, scenario=Scenario(…))` 在不改數據的前提下替換參數值、平移序列或指標，然後照常計算。
`Scenario` 有三種內容：`parameters`（換參數值）、`shifts`（全時段加減）、`ranged`（分時段加減）。

情境有兩種用法：

- **臨時試算**：請求裡帶上假設，算完即棄。煉廠頁面的「試算」是這種。
- **保存的情境**：`scenario` 和 `adjustment` 兩張表，由 `scenarios.py` 讀寫。每條調整 = 目標（序列或指標）+ 時段 + 加減量 + 依據。
  幾乎所有讀數的接口都接受 `?scenario=代碼`，所以任何指標都能在某個情境下查看。供需頁面的情境調整是這種。

調整加在序列上，會傳到所有用到它的指標；加在指標上，只影響該指標及其下游。
第四期的地緣事件會落成保存的情境（事件 → 一組帶時段的調整），推演引擎在多個情境之間比較。

## 7. 已知的簡化

這些地方目前是近似處理，用到時要心裡有數：

- 期貨存的是連續合約（M1 = 近月），沒有具體到期月份；換月當天的跳動沒有調整。
- 升貼水和官價的計價期用 M1 或當日現貨近似，沒有按實際計價月份對齊。
- 原油桶噸比用一個通用係數，沒有分油種。
- 機構預測只保留最新一版的值加修訂記錄，沒有按報告期號（例如「11 月報」）存成獨立的版本；
  用 `as_of` 只能還原「系統當時錄到的值」，補錄歷史報告時還原不出當時的發佈順序。
- 全球平衡表直接用 EIA 的分項，沒有分國別自下而上搭建。
- 關係模型是簡單線性擬合，沒有做滯後、分段或穩健性處理。
- 含稅模型裡，產品收入低於原料成本時增值稅為負（視為進項當期全額抵扣）；加工環節的其他進項不計。
- 沒有登錄和權限，操作者固定記為 `local`。
